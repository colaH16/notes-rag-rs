## 검증

운영 트래픽과 분리된 시험 배포에서 16개 검사, 실제 교체 후 서비스에서 같은 16개 검사가 모두 통과했습니다. 시험 웹은 별도 임시 SQLite를 사용했습니다.

- MCP 초기화·도구 계약, 공개/소유자 폴더 범위의 원본 비교, 인증 없는 요청 401·잘못된 Origin 403.
- 고정 프론트엔드 파일 12개, 보안 헤더, 익명 세션·폴더·그래프 API.
- 기존 `PG*` 환경 변수와 `verify-full` TLS 설정으로 실제 DB를 조회했습니다. 기존 인덱스 설정 서명과 일치해 재색인·스키마 변경이 필요하지 않았습니다.
- 실제 임베딩을 사용하는 MCP·웹 검색, 그 결과의 공개 문서 읽기, 로그인 리다이렉트의 PKCE/state/nonce 구성.
- 공개 HTTPS의 홈·그래프·상태·익명 세션 경로 200 응답.
- 기존 로그인·검색 예산 SQLite의 일관된 백업을 클러스터 PVC 내부에 보관하고 무결성을 확인했습니다. 기존 PVC와 DB 형식을 유지했습니다.
- 시험 Deployment·Service·검사 Pod·추가 네트워크 정책은 검증 후 삭제했습니다.

**검증 범위:** 실제 사용자의 로그인 완료나 기존 브라우저 쿠키 재사용은 사람이 확인한 결과가 아닙니다. 서명된 토큰을 사용하는 모의 OIDC 시험 12개, 기존 형식과의 호환성 시험, 실제 로그인 시작 리다이렉트까지 확인했습니다. Open WebUI 자체와 운영 부하 시험은 별도입니다. 성능 표는 [합성 로컬 측정](performance.md)으로, 운영 SLA를 나타내지 않습니다.

## 되돌리기

기존 GitOps의 두 Deployment를 이전 이미지·args 설정으로 복구합니다. 데이터 형식·PVC·DB 스키마를 바꾸지 않았으며, Python 생산자 잡과의 호환성 서명 검사를 계속 적용합니다. 진행 중이던 로그인은 전환 때 다시 시작해야 할 수 있습니다.

사용자가 RAG 보류를 해제하고 전체 적용을 승인해 검색·지도·원문에 공통 헤더와 V7 색상을 반영했습니다. 앱 소스 `553f47ab954202484204e6e96f445ce3b097d633`, 웹 이미지 `sha256:a414710b0307eec22dd35af3f17d8fe97a6b480ea844bee7eee33a653f70af4c`, [CI](https://github.com/colaH16/notes-rag-rs/actions/runs/41189528214)는 amd64·arm64와 격리 DB 통합 시험을 통과했습니다. GitOps `61-web.yaml` 이미지만 변경했고 MCP 이미지·PVC·환경·인증·검색·색인 설정은 보존했습니다. Deployment Ready를 확인했습니다.

Safari/iOS 실기, adoptedStyleSheets가 없는 구형 브라우저, 실제 계정 조작은 별도 범위입니다. 다른 사이트 포함 전체 운영 검수는 GitOps `scripts/branding/shared-header-v7-verification.json`을 봅니다.
